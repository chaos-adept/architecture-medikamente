# Задание 4. Оценка узких мест при миграции

## Общее описание

### Текущее состояние
Система строится на основе эклектичного хранения PII данных в виде excel.
Сканов, и простой файлов данных о пациентах. Без контроля доступа.
Что создает значительные риски, как для репутации компании, так и для пациентов в случае раскрытия их приватных данных.


### Цели миграции
 1. Интеграция лаборатории анализов с API
 1. Расширение направления обработки данных (новые сервисы на базе BI-, ML- и AI-технологий)
 1. Разработка новых систем
    - Портал клиентов
    - Портал ресепшена
    - Платежный шлюз
    - CRM для сбора данных о клиентах
    - Интеграцию с лабораторией анализов
 1. НФТ 
    - Конфиденциальность 
    - Масштабируемость (планируется открытие филиалов)
    - Сопровождаемость
    - Конфигурируемость
 


## Инфраструктура [критический приоритет]
### Проблема
Текущая инфраструктура это фактически просто локальная вычислительная сеть, с общим файловым хранилищем.
Что не может удовлетворить, как бизнес цели (например интеграция с апи анализов, создание порталов),
так и НФТ (работа с распределенными филиалами).
### Решение
- Миграция в облако для обеспечения масштабируемости и сопровождаемости, при органичных ресурсах (это не большая организация, без возможности вести поддержку своих серверов).
- Миграция в микросервисы с переносом в них данных и операции которые выполнялись ранее с excel файлами



## Программное обеспечение [высокй приоритет]
### Проблема
В данный момент над PII работа ведется в ПО Excel, что является существенной проблемой,
т.к. они не обеспечивает приватности и разгреничения прав доступа и множество других необходимых функций которые перечислены в целях.
Так же как и отсутствие ПО для обработки данных об анализах и обеспечения целостности данных.
### Решение
Миграция в новый системы/микросервисы и внедрение систем типа DataGail, должны удовлетворить потребности бизнеса через аудит контроль данных и скрытие данных.



## Интеграция [высокй приоритет]
### Проблема
Текущая проблема неявные связи между excel файлами и другими системами, в том числе 1с.
### Решение
Переход на микросервисную архитектуру с обеспечением разграничения доступа к информации и ее шифрования, маскирования, токенизации и скрытия.


## Персонал [критический приоритет]
### Проблема
В данный момент персонала недостаточно для удовлетворения целей бизнеса, тех.дир и сис.админ с бизнес аналитиком,
Не смогут самостоятельно разаработать такой широкий спектр систем за ограниченое время (первый этап пара месяцев, финальное состояние через год).
### Решение
В данный момент с учетом того, что один только найм может занять месяцы. Обратиться к подрядчикам по разработки ПО.
Параллельно начав найм сотрудников в штат на сопровождение и развитие экспертизы.


## Процессы [высокй приоритет]
### Проблема
Процессы в компании в данный момент во многом имеют ручной характер, где человеческий фактор может сильно повлиять на потерю, утечку и порчу данных.
Например администратор может случайно удалить все данные, скопировать их себе на флешку, или ошибиться к записью человека в определенное окно врача.
### Решение
Перевод процессов в распределенную среду с контролем целостности данных отслеживания утечек данных, аудитом правок, контролем непротиворечивости и целостности данных
